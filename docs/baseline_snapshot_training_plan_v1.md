# UW 快照 baseline 训练计划（精简版）

更新：2026-10-25。依据本轮用户审查意见调整；实施入口见[使用说明](baseline_snapshot_training.md)，数值配置见[快照配置](baseline_snapshot_training_v1.json)。本任务只有 MaskablePPO、DDQN、Threshold、minimum、maximum_feasible，不包含 LLM、Prompt、案例库或与 LLM 联合冻结。

## 1. 核心设置

历史模型来自 `results/uw2020_fit_v3/final_c05r28/`，锚点为 `results/e0_v5_iso0_w1trace/weekly_background_v1_local/control_anchor.json`。β=0.038583333332、人口69,457、历史初始感染100、教师2,321／职员21,596、campus_k_ts=3。员工社区边×0.1、ta=1.2×0.5=0.6持续保留；隔离和检疫系数保留实际非零值。

历史政策 c=.5、h=.1、recovery=.28，员工社区／ta／of／非本科社区／非本科宿舍限制为0。第x天起停止历史政策产生新行为，由baseline接管。重放拟合是合成控制任务的背景，不表示已知真实校园个体状态或现实因果效果。

| 设置 | 值 |
|---|---|
| 接手日期，day0=2020-08-17 | day21、35、49、63 |
| 主训练／调参时域 | 固定H112、16次自主决策、无固定首周 |
| 主报告条件 | day21、筛查容量5% N/日 |
| 容量 | 2%、5%、10% N/日，每回合固定 |
| 传播强度 | 历史及控制阶段均使用拟合β |
| 学习器seed | 11、22、33；三个模型全部保留 |
| 回报权重 | λ=1、γ=1；检测／通知／处置并集／活动各.25 |
| 预算 | 每算法每seed8192步；2048步验证一次；按2%改善规则最多延长到16384步 |

H不再由最低干预或其他方法的持续传播比例触发升级。终点活动感染是报告指标，不是重训门禁。可另做冻结模型140／168天延展，不重新训练，不回头用延展结果挑模型。

## 2. 共享快照与数据划分

| 集合 | 历史世界 | 日期与容量／分支 | 规模 |
|---|---|---|---:|
| train | [1000000,1100000)无放回选128个，选择只由schedule_seed=84001决定 | 四日期，三个学习器共用 | 512快照 |
| val（val36） | 20101–20109，共9个 | 四日期；按世界排序分3组各3个世界；每快照1分支 | 每候选36回合 |
| test | 50001–50020，共20个 | 四日期×三容量×两分支 | 每模型480回合 |
| pilot | 91001–91004，共4个 | 保存四日期，各世界运行一指定日期 | 4回合 |

总共161个历史世界、644个快照。val由配置 `validation_worlds=9` 指定：20101–20103使用2%容量，20104–20106使用5%，20107–20109使用10%，每个世界均运行day21、35、49、63。命令行split仍为 `val`，val36表示清单规模。history_seed在集合之间互斥，同一历史世界所有日期和未来分支归属同一集合。三个学习器共享初始状态分布，通过独立网络初始化、快照打乱顺序及包含learner_seed的future_seed派生来产生训练随机性；同编号PPO/DDQN学习器仍使用一致的回合计划。

训练专用过滤：day49／63且快照活动感染数（exposed或infectious且存活）为0时不采样。元数据在生成时记录该私有计数；它不进入控制器观察。val和test不读取此值筛样，报告零活动快照比例。过滤改变了训练分布，报告需明确；低感染但非零的快照保留。

每轮打乱所有保留快照，遍历后再打乱并更换future_seed，容量按历史序号和轮次轮换。过滤后“一轮”不再必然512回合，但8192步仍对应512个完整H112回合；绝不为了完整遍历补跑预算之外的步数。按实际step_count和完成episode_count计账，不统计空reset或未推进加载次数。

## 3. 状态保存、加载与政策移交

快照在完成[0,x)之后、执行第x天之前保存，sim.t=x，未finalize。保留人口／群组／接触拓扑、病程日期、康复／死亡、已知诊断、已有隔离／检疫及到期日、历史受检日期和待交付事件。未来种子不会重抽已确定病程。

训练和评估统一以磁盘快照为起点。加载后一次性设置Python、NumPy和Numba随机流；不逐周重新设seed，也不要求恢复“未落盘时连续运行的全局随机流”。学习器与模拟器在独立进程运行。

停止历史检测／追踪和接触限制。恢复保存的未施策边权，不能用除法解除为0的乘数；维持员工社区和ta背景，然后执行新动作。已有隔离／检疫和排程事件继续，历史检疫保留原10天到期，新检疫仍按14天规则。不把恢复接触权重误作解除隔离。

生成时将状态文件哈希写入 `snapshots_manifest.json` 留档。每次读取只检查存在、内部version及轻量世界／日期标签，不重算状态文件、公共历史或源码哈希。新状态版本为 `uw-snapshot-control-v1`，不接受旧格式，不自动回退day0。生成和正式建库仍使用已核验的E0锚点；此项精简不改写校准证据。

固定路径文件写入使用独占创建，防止覆盖真实数据；缺文件、版本不符或非法动作直接报错。这里不引入恢复重试、默认静默替换或动作失败状态机。已有动作mask仍保留，但mask不能保证调用方或模型文件永远没有bug，报错用于暴露实际错误。

## 4. 观察与训练终点

快照RL输入版本为 `cemas-snapshot-public-float32-v2`，197维。保留最近四周和公开人口、资源、处置、当前动作。每周只增加 `is_history_week`，另保留原 `week_valid` 区分左侧缺周；总检测保留，因为历史检测没有临床／筛查分类。

历史缺失的动作、容量、检测拆分、通知及活动负担位置填0；is_history_week=1表达这些字段共同缺失。JSON日志用null表达缺失，不维护字段级Flag矩阵、自然语言政策转换或LLM Prompt。Threshold继续只看最近有效周的诊断数和增长。

移除decision_day/H、execution_days及历史周起止日/H这些显式时钟输入；保留公开接手日期。动作持续天数用固定112尺度，与实际延展时域无关。部分状态或动作持续信息仍可能间接透露时间，因此不声称彻底消除了时间推断。

到112天时，快照Gym返回 `terminated=False, truncated=True`。MaskablePPO使用现成库的TimeLimit处理，给最后reward加γV(terminal_observation)；DDQN保存截断前terminal_observation和next_mask，replay的真正terminal标志为false，让Double target继续bootstrap。不能把自动reset后的新世界观察用于该target。旧day0任务仍保留真正终点、不bootstrap的语义。

**这是训练目标变更，不是单纯删代码。** 正式评分是112天有限区间的实际J；训练target额外包含延续价值近似。γ=1加上持续干预成本，不能保证任意策略都有有限无限时域价值，也不能保证消除期末投机。记录训练曲线、value/Q稳定性和第112天活动感染，不能把bootstrap后的训练target当作正式评分。

## 5. 成本与跨界事件

`J=I_after/N + λ×[.25 Tests_after/(.12NH)+.25 Notifications_after/(.10NH)+.25 UnionDays_after/(NH)+.25 ActivityDays_after/(NH)]`，主实验H=112。

通知在接手后交付就计入，不加来源分账。事件对象保留到期／合并必需的信息，不增加第二套来源审计。继承隔离／检疫的接手后人天计入；接手前已做的检测不重复收费，结果交付仍影响公共观察。历史传播乘数不当作活动人天。

接手时保存一个 `cum_infections_at_x` 标量。Covasim运行中的cum结果尚未finalize，标量实际由初始感染和前缀new_infections之和取得；终点由finalize后的累计减去标量得到I_after。逐周reward继续使用当周感染流量，私有账本只累计接手后感染，不携带历史感染偏置，也不实时维护两套历史账。

140／168天延展沿用训练时112天的负担归一化分母，防止reward含义或输入尺度悄悄改变；延展成本属于更长区间，单独报告，不与112天J混成一张排名。保留第112天活动感染以便核对同一前缀。

## 6. 单验证集选模与独立测试

PPO/DDQN网络、学习率、rollout／batch、预热和更新频率保留原配置。三个学习器每2048步在同一val36清单评估；每seed直接按最低平均实际J选checkpoint，平局选较早步数和稳定ID。预算升级仅看val，最多16384；不再跑B复选。

Threshold32个候选全部在val36评估，选最低J，平局按活动负担再按候选ID。minimum和maximum_feasible各用同一清单。baseline选模完成即可独立运行test，无LLM、memory、案例库或共同H锁。

| 阶段，8192步基准 | 回合数 | 接手后模拟日 |
|---|---:|---:|
| RL训练：2×3×8192/16 | 3072 | 344064 |
| RL checkpoint验证：2×3×4×36 | 864 | 96768 |
| Threshold：32×36 | 1152 | 129024 |
| 固定参照验证：2×36 | 72 | 8064 |
| 开发合计 | 5160 | 577920 |
| test：9个保留策略×480 | 4320 | 483840 |

另计历史前缀161×63=10143模拟日和快照存储／读取、pilot及失败重做。共享库比原1740份减少约63%快照。相对上一版val72，验证工作量从4176降为2088回合（467712降为233856模拟日），减半；RL训练量不变，开发合计从7248降为5160回合，减少约28.8%。这些是相同H下的模拟工作量，实际耗时还受训练更新及读写开销影响。验证历史世界从18减为9，每容量组仅3个独立世界，选模均值的采样波动可能更大；test维持20世界、480回合／模型。

所有方法使用同一 `(history_seed, day, capacity, future_seed)` 清单。主表为day21＋5%容量，共40回合／模型；附四日期三容量分层、等权总体。报告J、感染和负担分量、学生／员工新增感染、第112天活动感染、零活动快照比例。test包含20个独立历史世界，两个未来分支不当作独立历史样本。

区间以history_seed为聚类单位，对全部方法／日期／容量／未来分支配对重采样；RL学习器另重采样。10,000次、seed83001，95%区间。`compare`生成五baseline独立报告，不等待其他方法。不得用test结果重新选阈值或checkpoint。

## 8. 核心验收与范围

1. 保存／加载静态人口、疾病日期、处置到期和接触边一致；边界不再次注入初始感染。
2. 同磁盘快照、相同future_seed和动作序列，两次112天逐日结果相同；换seed保留初态但改变未来。
3. 不同策略及reset互不污染原状态文件。
4. 首观察仅截至x−1；缺失位置和历史标记正确；112天16动作，跨界事件和新增感染只按接手后计费。
5. train／val／test历史世界互斥；val/test不筛零感染；三个学习器共享同一训练池。
6. PPO/DDQN时间截断bootstrap、terminal_observation／mask、实际梯度更新及保存加载通过；val选模无第二轮；五方法测试和报告独立可用。

代码及小规模验收不等于正式128世界建库、三seed完整训练或480场景比较已经完成。已存在的旧259维模型、旧快照包和A/B报告保留历史用途，新版本不自动复用。
