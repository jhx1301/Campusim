# 验证方案、研究定位、实施路线与未决问题

日期：2026-10-17。本文是设计与未来验收计划，不是实验结果。当前主方案为**单次独立请求的单控制器，配合程序确定性生成的近期摘要、版本冻结的专家知识与公共案例检索**。主方案没有 LLM 反思器、经验写入器、在线审查器、世界模型或额外模拟查询。与主方案对应的字段、检索与提示词以本目录架构及提示词文档为准；本文规定如何证明它们正确、何时允许做效果实验，以及什么结果才足以支持论文主张。

## 1. 证据状态与总体验收原则

现行 [P4 契约](../control_phase4_contracts.md)先登记过 472 项离线回归与离线闭环通过，后续预算修订的最新历史登记是 **572 passed、1 failed**，失败为当时环境缺少 `tokenizers`；相关后期原始验收目录在本次 checkout 未找到，不能独立复核。人口登记/标定源码变化还使旧 E0 产物需要重新生成并验收。真实 provider/tokenizer 验收仍待完成；这些均不是本次重新运行得到的结果，不能以旧472项通过代表当前全量通过，详见[现状基线](00_current_baseline.md)。本次任务不调用收费模型、不安装依赖、不执行正式仿真或训练。因此以下所有“通过标准”都是将来的门禁，不能改写成“已通过”。

四类结论必须分开记录：

| 类型 | 本项目可作出的结论 | 不可据此作出的结论 |
|---|---|---|
| 结构验收 | 输入字段、时间顺序、动作解析、引用 ID 与落盘机制符合契约 | 模型会选到更好的档位 |
| 真实 API 验收 | 指定模型/路由/指纹在指定请求参数下能返回、预算与计数相符 | 全回合可靠、实验效果已确认 |
| 源域开发 | 某个冻结候选在预定开发或验证样本上表现较好 | 对目标测试或现实地区有效 |
| 冻结测试 | 同任务、同观察、同目标的预定比较得到带区间的效果 | 单案例动作的因果效果、临床有效性、现实部署安全性 |

工程门禁遵循“结构正确优先于效果”。允许一次合法但质量不佳的提案进入共同执行链；禁止通过私有奖励、事后结果或 LLM 自评分在运行中替换它。所有正常重试耗尽使用既有共同回退；基础设施、配置或身份错误按 P4 停止当前周，不伪造完整回合。

| V26 | 首窗与次窗revision同时存在；冲突对不在最终发送列表、预算裁剪删除已选例 | 一个case_id只读取冻结manifest指定的最后有效revision；引用注册表只含最终发送内容；冲突提醒的来源与裁剪状态可审计，不能声称模型比较了未发送反例 | 冻结快照、排序与预算裁剪组合测试 |
| V27 | 38维state、趋势差分、零学校/工作人口、day0，以及检索各阈值恰好等于/略过边界 | 维度与尺度一一对应，差分仅归一化一次；分母为0的活动维无效；day0只匹配day0；边界包含关系、冲突对优先级和同分排序唯一确定 | 精确小数fixture；对`.75`有效比例、`3`state RMS、`.35`score和容量差门槛作边界测试 |

V01–V17、V19–V27 中确定性条目要求全部通过，不能用“平均通过率”掩盖一次泄漏或时间顺序错误。V18 的语义检查分为可自动检出的词法/字段冲突与需人工判断的含义冲突；后者是评估结果，不是声称绝对可靠的运行门禁。

主设计不会生成逐周自然语言教训，因而没有“reflection prompt 验收”或 LLM writer 重试路径。所有 case 的计数、窗口、趋势、负担、标签、模板文本均由公共数据和固定规则生成。若以后增加反思，应注册独立实验配置、完整模板与写入验证；不能将其悄悄放入主方法。

## 3. 指标及其信息权限

### 3.1 首要效果指标

统一主指标保持 [协议](../control_protocol_v1.json) 的未折扣有限时域正成本：

`J = I/N + λ × (w_T Tests/(.12 N H) + w_L Notifications/(.10 N H) + w_Q UnionDays/(N H) + w_A ActivityDays/(N H))`。

数值常量运行时必须从冻结协议读取，不在新模块再定义第二套。I 是初始之后的新增感染事件，仅私有评价使用。新增记忆不能接收 I、J 或其排名；源域离线研究者可以用统一 J 选开发版本，但该选择、版本与数据用途须在测试前固定。

现行预定主比较继续是 `llm_full − maskable_ppo`、`llm_full − double_dqn` 的按世界配对 J 差。架构研究增加的核心机制比较是 `llm_full − llm_no_explicit_memory`；它属于明确新增的预注册比较，不能在结果出来后挑选最有利组。若主张“记忆改善”，同时报告 none/short/global/both 的配对差及区间；不能因其中一个指标好看就换主指标。

### 3.2 次要与诊断指标

| 类别 | 指标 | 读取权限与解释边界 |
|---|---|---|
| 感染 | 新增/累计感染、日峰值、终点活动感染 | 私有分析；不得供在线 retrieval 排名、案例 success 标签或解释 |
| 公共代价 | 临床/筛查人次、交付通知、隔离/检疫/并集人天、三类活动限制人天 | 程序精确聚合；诊断减少不能直接当作感染减少 |
| 动作行为 | 每维档位分布、切换次数、绝对档位变化、请求非法率、S 调整率、回退率 | 不默认“更平滑/更强/响应更快”更好；与 J 和成本共同解释 |
| 案例使用 | 查询返回数、低覆盖率、资源/窗口不适配率、重复率、每动作覆盖；另做每来源世界覆盖审计 | 前者由公共检索侧计算；来源世界数只能由离线私有建库索引核对，不进入controller/query/prompt；仅“检索过”不等于“使用过” |
| 证据质量 | 引用存在率、引用输入覆盖率、字段支持率、错误因果断言率、遗漏限制率、解释与动作冲突率 | 程序检查存在性；含义和相关性由盲审；不把引用存在率称忠实性 |
| 不确定性 | 八项wire枚举：`partial_observability,no_history,testing_changed,capacity_changed,no_case,case_conflict,out_of_support,truncated_followup`；检查是否包含程序`required_flags` | categorical code不是校准概率；所有模式要求`partial_observability`，只有启用global但空/失败才强制`no_case`；高不确定性不能当作免责理由 |
| 稳健性 | 无关文本/顺序扰动的动作差异，重要证据去除的行为变化，冲突案例注入影响 | 只能检验输入—输出敏感性与自洽性，不能证明内部推理机制 |
| 运行成本 | 调用数、输入/输出/推理 token、cache hit/miss、总延迟与 p50/p95、失败重试耗费 | 保存实际 usage；无实际计数时标缺失，不能以字符数代 token |
| 离线成本 | 源库采集模拟日数、构建/索引耗时、存储大小、模型依赖、训练/调参预算 | 与在线预算分开报告；不能把建库当作免费或零样本 |

主方案不预测隐藏感染，也不输出校准概率，因此不报告感染预测 MAE 或 Brier score。如果将来增加公共后效区间预测，应先明确预测目标是“交付诊断”等可见变量，使用严格前序预测与适当 scoring rule；不能在看到反馈后生成所谓预测。

### 3.3 统计单位与失败

采用现行每条件 20 个世界、world-block 配对 bootstrap 10,000 次、统计 seed 83001、95% 区间；RL 的三个训练 seed 按协议重采样，不能复制一条 LLM 轨迹三次增加样本数。周、案例、同一轨迹的四个策略窗口不是独立样本。源库检索诊断按 episode/world 分组报告，避免把 1,728 个高度相关周案例当作 1,728 个独立环境。

正常 API 失败与回退留在效果统计中。基础设施错误保留失败身份，按同版本重放；无法补齐时报告缺失数与原因，不能静默剔除。报告配对均值差与区间，不以“p>0.05”宣称等价；若要主张不劣，需要在源域 pilot 后、目标测试前预先确定有实际意义的不劣界及功效分析。当前不发明“至少提高 5%”的效果保证。

## 4. 实验控制：分辨记忆内容、额外信息与额外计算

### 4.1 冻结与数据用途

| 用途 | 现行世界池 | 允许工作 | 禁止工作 |
|---|---|---|---|
| 离线 smoke | 90001/90002 | 类型、闭环、失败路径 | 科学效果结论 |
| 提示开发 | 40001–40009 | 结构、输出格式、服务验收 | 读取目标测试调 prompt |
| 案例采集 | 30001–30027 | 九源域组合×三个世界×四采集策略 | 用目标世界补库；按私有收益筛掉“不好看”的经验 |
| 验证 A/B | 20001–20009 / 20101–20118 | A筛候选、B固定唯一版本及H/资源边界 | 反复看B直到得到理想结果而不记录搜索 |
| 最终 E1/E2 | 50001–50020 | 冻结后一次预定比较、合法轨迹复用 | 改模型/知识/库/阈值/案例选择规则 |
| 最终 E3 | 60001–60020 / 60101–60120 | 合成人口/网络迁移 | 用城市结果补训练或记忆 |
| 最终 E4 | 70001–70020 | 当前资源揭示后的动态响应 | 提前提供解锁日；不同方法拿到不同前缀经验 |

同一个 world 的全部策略轨迹、相邻周和文本变体必须归同一折。对源库覆盖与检索开发使用按 world 留出的交叉验证：一折世界的四策略全部留出，其余世界建索引，不能让同世界另一策略或下一周充当近重复检索答案。最终冻结库可使用规定采集池的全部合格轨迹，但不得包括验证或目标世界。

27 世界×4策略=108轨迹、H=112时最多1,728完整周，只是现行采集计划上限。必须生成覆盖报告：九情景单元、有效历史长度、诊断/增长区间、动作持续时间、当前/执行动作、容量、后效方向、负担权衡及来源世界数。没有必要要求324组合各出现相同次数；必须解释检索到的动作支持是局部且稀疏的。若关键区间只有单世界或单策略支撑，报告低覆盖，不给它“充分证据”标签。

是否扩展采集先由源域覆盖与 leave-world-out 结果决定，新增世界池和策略必须写入新协议版本后再采集。不能临时用 final-test 世界填空。推荐第一轮保持现行池，以结构基线验证机制；只有观察到可重复的覆盖瓶颈才增加采集，记录其模拟预算。

### 4.2 必需消融与负对照

| 比较 | 保持不变 | 识别的问题 |
|---|---|---|
| none/short/global/both | 模型、任务规则、原始四周、专家知识、输出 schema、采样、种子世界、resolver | 近期结构化组织与跨回合公共案例的边际收益 |
| 结构检索 vs 原 v1 混合相似度 | 同库、同k、同展示字段及预算 | 可选文本 embedding 是否值得依赖与计量成本 |
| relevance ranking vs 固定随机合格案例 | 同案例数/字段长度分布、相同 source-only pool | 收益是否来自情景相关性，而非多看示例 |
| 完整公共后效 vs 仅状态/动作 | 同检索ID、同动作覆盖 | 后效和负担是否参与选档；删去内容后的 token 差另报 |
| 带适用性/滞后标签 vs 无标签 | 同原始公共案例 | 显式限制是否减少错误归因并改善资源变化下决策 |
| 主知识集 vs 六条现行规则 | 所有其他模块 | 外部知识是否提供新增信息；若无收益可回退精简集 |
| 主模型 vs 预定异系列模型 | 同冻结知识/库/模板语义、同公共上下文 | 结果是否只依赖单一路由；两供应商参数差异如实报告 |
| 原始案例顺序 vs 稳定重排/无关文本 | 同内容与预算 | 顺序和叙事偏置；仅属诊断，不能用最有利顺序作最终结果 |

负对照不允许把错误知识作为正式主方法输入。知识bundle的未解决conflict_pairs在加载阶段拒绝，不交给模型裁决；同conflict_group不是冲突。另在独立鲁棒性fixture中注入相互矛盾的公共案例、无效引用、资源不适配案例，记录模型与程序如何响应。不可把所有诊断当作动作之后的直接效果，或通过事后挑“成功案例”制造检索优势。

### 4.3 单控制器、审查器与多角色的公平比较

主方案每周一个逻辑决策调用，最多三次 P4 技术/解析重试；其余步骤均为程序。多代理仅为预注册研究分支，先做静态决策 fixture，再决定是否值得全回合评估。禁止为多代理提供更多观察、私有指标或额外模拟 rollout。

| 研究分支 | 调用结构 | 权限与裁决 | 要检验的故障 |
|---|---|---|---|
| S1 | 一个控制器，一次回答 | 单个公共上下文，原 resolver | 主方案基线 |
| S-long | 单控制器提高允许推理/输出预算 | 与 S1 完全相同 | 单纯增加推理预算是否已解释收益 |
| S-refine | 同角色两次调用：初稿→在同公共材料上修订 | 不增加信息；最终输出通过同 parser | “再想一遍”的收益与错误传播 |
| C-review | 控制器→证据审查器，一次审查 | 审查器仅见公共上下文和提案；只可指出可引用证据、资源、解释错误；通过则保留，失败则按预注册规则返回共同fallback，不自行创造第六动作 | 第二角色能否抓到初稿错误，是否误否决正确提案 |
| M3 | 疫情/资源负担两个独立建议者并行→一个整合者 | 两者同公共输入、分别输出受限建议；整合者必须选择合法组合并列出冲突；无通信循环、无多数决“证明正确” | 分工是否改善实际权衡而非制造一致叙事 |
| Ensemble3 | 三份独立同角色回答→固定 action_id 多数票；平票取最早有效回答 | 与 M3 相同模型调用数量和资料；整套动作投票，不逐维拼接/数值平均 | M3收益是否仅来自多次采样 |

此表是比较设计，不是主实现要求。新增分支的提示词、解析和裁决必须在其运行前完整冻结；本目标交付的主方案提示词不包含这些未采用调用。C-review 的语义否决可能使其fallback率增加，因此需要同时报告接受正确初稿率、拒绝错误初稿率、错误否决率，以及J；不能只挑被纠正的例子。

预算对齐至少两种口径并列，不能互相冒充：

1. **相同请求上限**：总输入/输出/推理允许量按各调用分配，S-long/S-refine/C-review/M3/Ensemble3使用同周总上限。记录未用额度；“相同cap”不等于相同实际token。
2. **实际资源 Pareto 比较**：报告同模型实际输入、输出、推理、缓存、调用数、费用与墙钟时延；绘制 J—token、J—时延前沿。供应商不返回分离 reasoning tokens 时不得声称“精确同推理计算量”，退而报告可观测总usage与请求上限。缓存命中按实记录，不能从经济成本推导认知信息增加。

API重试也是成本，不能将失败分支的额外调用从预算统计移除。若供应商不能严格限制跨调用推理量，则将“同总cap”和“实际usage分布”写入论文限制，而非声称严格等算力。技术重试预算、正式推理预算及源库离线采集成本应分别报告。

已有对照研究给出相反方向的结果：Huang 等对 intrinsic self-correction 的研究提示无可靠外部反馈时修订可能退化，并要求匹配调用预算；它不否定所有审查方法。[原文 §3、§5、§7](https://arxiv.org/html/2310.01798v1)。2026 年 Wunderlich 等在 MMLU-Pro/BBH 和 Llama 3.1 上发现合适配置的多代理可位于更好的计算—准确率前沿，但成本为理论估计、样本有限，未测疫情控制。[原文 §4 与 Limitations](https://arxiv.org/html/2605.01566v1)。Tran/Kiela 的多跳问答实验在匹配请求 thinking cap 下支持单代理，且明确没有强迫实际用满预算，也不覆盖工具和安全场景。[原文 §4、Appendix C](https://arxiv.org/html/2604.02460v1)。因此本项目选择单控制器是当前约束下的设计判断，不是宣称多代理普遍无效。

## 5. 可证伪研究问题与创新判断

### 5.1 最近邻差异

检索与全文核读日期均为2026-10-17。下列是论文报告内容；没有在本项目复现其数值，也不把其性能直接外推到CEMAS。

| 原始工作与已核读位置 | 与本项目重叠 | 关键差异及本项目应提供的新增证据 |
|---|---|---|
| Aoki & Ghaffarzadegan, *AI Agents as Policymakers in Simulated Epidemics*，2026-01-06；[§2.3、§3、§4及附录](https://arxiv.org/html/2601.04245v1) | 周期决策、近期记忆、知识注入、单与ensemble比较 | 文中recency采样五条记忆、十次独立推理平均；单一限制变量、近乎完整的周病例和正确因果结构知识。本项目需检验受检测行为影响的延迟交付、五维容量动作、来源冻结案例及统一多项负担目标，不能声称首次“疫情LLM+memory+knowledge”。 |
| Memon 等, *EpiWorld: Grounding LLM Policy Agents in Epidemiological World Models*，2026-10-02；[§3.4–3.5、§5、Appendix I/L、Limitations](https://arxiv.org/html/2610.02744v1) | 公共卫生规则、案例/lesson检索、反馈积累、可解释决策 | 已有分层skill、learned world model反事实评估、周期teacher与lesson修订；其跨regime负迁移实验表明知识复用需要适用边界。本主方案不查询任何world model，不用模拟未来或私有收益写案例；需要以严格相同信息检验适用性、滞后与来源可核查机制，而非把“有RAG”称新方法。 |
| Lu 等, *EpiEvolve: Self-Evolving Agents for Streaming Pandemic Forecasting under Regime Shifts*，2026-06-03；[§3–5、Limitations](https://arxiv.org/html/2606.05513v1)，核读记录见[证据E25](01_research_evidence.md#e25--epievolve延迟反馈经验和情景检索也已存在) | 延迟标签、近期/长期经验、情景检索、经验修订 | 对50州81周住院趋势作五类预测，先固定全周预测再揭示标签，随后反思与规则更新；这说明“延迟反馈+检索+经验演化”也不是独有创新。本项目干预决策没有单动作正确标签，故不能把公共诊断变化照搬为预测误差或策略成功；需证明无因果标签条件下的可观测案例机制。 |
| Shi 等, *Coordinated Pandemic Control with Large Language Model Agents as Policymaking Assistants*，2026-01-14；[方法与Discussion](https://arxiv.org/html/2601.09264v1) | 多轮疫情决策、LLM政策、模拟比较 | 多agent对应不同地区及真实跨区流动外部性，主要动作是区域流动控制；CEMAS现阶段只有统一共同目标与单公共观察，不能照搬地区角色再声称分工必要。需证明五维资源/反馈任务中的具体分工收益。 |

目前“单LLM+结构化近期记忆+案例检索+专家知识”的组合属于**工程整合与任务适配**。公共/私有隔离、回放与严格解析是研究可信度所需的基础，不自动构成算法创新。若最终只有主方法优于一个较弱基线而无机制消融、强近邻对照或跨条件证据，面向综合多智能体期刊/会议的创新性不足。

可争取的方法贡献应收敛为：**在动作会改变观测过程、反馈延迟且资源变化的部分可观测控制中，以可核查公共经验而非隐藏收益指导档位选择**。其最小具体方法是固定的适用性检查、滞后/窗口/测量变化标注、相互矛盾经验保留、可引用证据输出与严格冻结。只有这些组件的消融带来可重复且有机制解释的改善，才能把工程设计提升为方法证据；该效果目前未知。

### 5.2 研究假设

| ID | 可证伪假设 | 最小证据与反驳情形 |
|---|---|---|
| H1 | 公共案例的状态/动作/资源/后效对照可降低统一J | 对比full与none/global ablation；若优势消失、区间宽或仅某个测试世界有效，则不支持普遍改善 |
| H2 | 确定性近期组织改善延迟趋势的利用 | 原始四周均保留的short对none；若仅因多token或顺序改变产生差异，需负对照而不能归于“记忆能力” |
| H3 | 适用性与滞后标签减少资源不适配和错误因果解释 | 标签消融、延迟/资源fixture与E4；若只是更谨慎措辞而动作/J不变，则只支持说明质量，不支持控制性能 |
| H4 | 低覆盖/冲突提示有助于避免不当类比 | 预定OOD/冲突fixture、按程序旗标分层；若更高fallback但无J改善，需报告成本与限制 |
| H5 | 在本任务预算下单代理达到合理效果—成本折中 | 与预算匹配S-long/C-review/M3/Ensemble3比较；多代理若稳定改善且成本可接受，应重新选择架构 |
| H6 | 来源化证据输出提高外部可检查性 | 引用/字段/适用条件检查及盲审；若只生成更多合理文字而无字段支持，则失败；不声称读出了内部思维 |
| H7 | 源域案例可迁移到预定合成人口/资源变化 | E3/E4冻结测试及负迁移诊断；只支持这些合成条件，不支持任意真实城市或疾病 |

解释研究尤其要避免把自然语言的流畅度视为忠实性。Turpin等显示解释可能掩盖输入偏置，Lanham等通过干预reasoning文本发现其因果作用随任务和模型变化。[Turpin等原论文](https://arxiv.org/abs/2305.04388)、[Lanham等原论文](https://arxiv.org/abs/2307.13702)。本方案只承诺记录“给过什么公共证据、模型引用什么、哪些字段通过检查、最后执行什么”，不承诺重建模型内部原因。

### 5.3 面向论文的最小贡献包

建议以一个明确问题组织论文：**可观测经验如何帮助有限预算LLM在测量受行动影响的序列控制中选档，同时保持信息公平和证据可检查？**

必须至少具备：冻结公共基准和数据划分；较强RL/阈值/无记忆LLM基线；完整记忆消融；与recency或普通相似检索的机制比较；延迟/资源/OOD的预定诊断；统一负担目标与原始指标；API成本和失败；两模型有限复核；复现所需的提示、源库hash与响应记录。若只能完成其中一部分，缩小论文主张，不将未实现模块写为贡献。

正式名称、研究范围与目录状态已在2026-10-17核验：期刊是 *Autonomous Agents and Multi-Agent Systems*，[Springer官方范围](https://link.springer.com/journal/10458/aims-and-scope)明确覆盖自主agent的决策架构、学习、协作与评估；会议是 *International Conference on Autonomous Agents and Multiagent Systems (AAMAS)*，[AAMAS 2026官方welcome](https://www.ifaamas.org/Proceedings/aamas2026/pdfs/welcome.pdf)将其列为第25届，并列出learning/adaptation、Generative/Agentic AI、simulation等主题。[CCF官方AI目录](https://www.ccf.org.cn/Academic_Evaluation/AI/)（直接抓取曾返回405，检索索引仍能核对条目）将该期刊以AAMAS缩写列为B类、会议列为B类；这是当前可访问目录的分类记录，未确认有更新的官方目录，不是本项目达到该级别的保证。AAMAS会议与期刊是不同发表渠道；本文不凭简称“JAAMAS”或历史目录等级承诺适配/录用。投稿前应再次核验当年call、期刊scope与CCF目录版本，重点说明自主决策、反馈学习或agent方法的可推广贡献，而非只强调疫情应用。

## 6. 需要显式登记的协议与兼容变化

以下均是未来实施提案；本次没有修改 `control_protocol_v1.json`、业务代码或旧数据。

| 变化 | 当前状态 → 提案 | 兼容与公平影响 |
|---|---|---|

| 额外知识 | 固定六条规则 → 分型版本知识清单 | 不改任务动作阈值或目标；现实指南仅作限制与解释参考；无记忆组同知识输入 |
| 新研究比较 | 原主比较/四记忆消融 → 增加机制负对照、解释质量及预算匹配架构比较 | 不改变原主比较；新增测试预算和多重比较计划须预注册 |

默认不需要改变 `PublicObservation`、`PublicInfo`、奖励公式、日周时间顺序、五维动作、合法mask或执行器。反馈已含实际执行向量与资源，记忆可以在`observe(feedback)`确定封闭动作窗口；若开发者需要执行调整原因，只能通过独立公共白名单导出，不能为了方便读取整个`DecisionRecord`。任何增添更长历史、未来预测服务或隐藏状态估计输入都属于新的信息条件，需另立协议与同信息基线。

命名是推荐模块拆分，不要求为每种数据创建单独抽象层。`memory_types.py`集中公共不可变类型，`memory.py`承担生命周期，`retrieval.py`承担排序，`knowledge.py`承担静态筛选；它们不依赖environment/simulator。runner负责私有来源映射、调用审计与最终评价，controller只有公共输入。

优先顺序是先确定性模块和可回放fixture，再验收真实服务，再采集源库与做效果实验。若结构检索足够有效，可以保留无embedding主方案；若短期摘要没有收益，可以去掉附加短期文本并保留原四周历史。删减需要由源域证据决定，不在目标测试中改架构。

## 8. 集中未决事项

| 问题 | 原因与影响 | 当前默认选择 | 替代方案与后续判定 |
|---|---|---|---|
| 真实DeepSeek/Qwen服务与官方tokenizer是否匹配 | P4尚未真实验收；影响全部在线预算与复现 | 沿用生产门禁，离线只验证控制流 | R4真实三类基础+四记忆消息；失败则修适配/服务配置，不借用估计器 |
| 27×4库是否足以覆盖选档 | 周案例相关、策略覆盖有限；相似≠最优 | 保持初始池并显式低覆盖/空检索 | 留world-out与coverage报告后决定增加来源或策略，不读取测试 |
| embedding是否有净收益 | 公共输入多为结构化数值；向量依赖与语义偏置成本 | 主方案无embedding；向量仅为独立冻结对照 | 同库/同k/同预算对照；有稳定收益才升级主方案 |
| 适用性/OOD阈值 | 没有本任务校准证据，过严会失去经验、过松会误类比 | 使用架构中明确的开发默认值并标低证据；不把其当理论最优 | 在source A选择、B确认并冻结；目标测试只诊断 |
| 新wire输出是否影响行动质量 | 更复杂JSON增加解析失败与token | 版本化候选；程序验证后转原ActionProposal | 与旧action/reason在源域比较失败率/成本/J；必要时保留旧wire+程序元数据 |
| 模型证据引用是否忠实 | 存在引用不证明其真正驱动动作 | 只宣称可核查外部证据；不索取/存储完整内部思维链 | 盲审与证据删改敏感性；仍不能证明内部机制 |
| 现实指南与合成动作的映射价值 | 真疾病、真实阈值与本任务成本/执行语义可能不同 | 分型、限定场景；不把指南变为硬动作阈值 | 六条规则vs额外知识消融；无新增价值则精简 |
| 在线审查或多agent是否值得 | 文献任务相互矛盾，本项目没有效果数据 | 主方案单调用无审查 | 预算匹配分支；有稳定增益和可承受成本才重新选择 |
| 是否引入LLM反思 | 公共反馈不支持可靠因果/成功标签，额外语言可能固化错误 | 全部记忆确定性生成，不调用反思器 | 先建立可审查因果/反馈信号再单独研究；当前不预留默认调用 |
| H和目标权重最终冻结 | 当前development_candidate；影响经验窗口/归一化与结果 | 沿用现行Phase6源域H门禁和统一目标 | H变化所有方法统一重开发/重采集，不只修LLM |
| 期刊/会议创新性是否足够 | 2026近邻已有memory/knowledge/world-model policy agent | 将贡献定位为可观测经验机制的可证伪研究 | 需强基线、机制消融、预算和迁移证据；无实验不得判断达到录用标准 |

剩余不确定性都可用上述最小试验回答。它们不妨碍实现主架构，但会限制性能、成本、泛化和论文创新性的最终主张。完成本文所述设计，只证明实施者有明确路线和验收边界。
