**1．参数清点：先分清环境配置、在线观察、动作参数和算法超参数**

当前 `covasim/parameters.py::make_pars()` 显式定义 **75 个顶层参数键**，见附录 A。这个数不包括嵌套字段、干预类参数、LLM/记忆参数、RL 超参数和实验配置，也不是需要调优 75 个参数。扩展干预与 `kwargs` 会引入更多配置，整个系统不能用一个固定总数概括。

| 参数层 | 覆盖内容 | 控制器可见性 |
|---|---|---|
| 人口、网络与时间 | 总人口、年龄/角色构成、班级/实验室组织、接触层、动态网络规则、日期、时域、初始感染、缩放 | 公开总量、聚合结构和日程可共同提供；个体微观状态/本次隐藏网络细节不自动公开 |
| 疫情生成与疾病过程 | beta、各层传播系数、个体传染性分布、病毒载量、外部输入、病程、严重度、免疫、再感染、变异 | 可披露共同先验和源域范围；本回合隐藏抽样值与个体真实过程不能在线提供 |
| 干预和固定病例处置 | 限制、概率检测、周期筛查、追踪；隔离/检疫效果及期限；检测敏感度和报告延迟 | 公开的动作定义、当前执行档位和固定处置规则共同可见；尚未发生的结果不可见 |
| 资源和执行约束 | 筛查/检测/追踪容量、分组优先级、排队、合法组合、按维度的保持/升降规则 | 当前公开容量及共同合法集合可见；不提前告知未来事件 |
| 观察与数值编码 | 字段、聚合窗、交付延迟、归一化、缺失填充、历史有效长度 | 各方法获得相同基础信息；LLM 文本与 RL 数值编码须可对应 |
| 目标与统计 | 感染事件、检测次数、通知人次、隔离/检疫人天、活动限制人天、固定尺度、lambda | 目标定义公开；真实感染与真实奖励仅源域训练/私有评估使用 |
| LLM 与记忆 | 模型、提示、生成参数、重试、上下文、记忆窗口、检索数量、相似度权重、embedding、库版本 | 算法配置可公开；不能因此将隐藏疫情真值放进记忆或反馈 |
| 基线算法 | PPO/DDQN 超参数、阈值搜索、固定参照 | 属于训练/算法设置，不属于疫情在线观察 |
| 实验和复现 | 场景范围、种子、划分、预算、并行、运行标识、日志、版本 | 提供执行协议；隐藏场景标签、世界 seed 和真值日志不默认输入控制器 |

- [ ] 固定第一阶段人口/时域/疫情条件。当前库默认 random、20,000 人、60 天；t17 默认 campus、40,000 人、84 天；t18 校准用 campus、12,000 人。三者不能混用。

- [ ] 固定是否使用免疫衰减和再感染。当前库 `use_waning=True`，不能只依据论文 SEIR 图假定“一人最多感染一次”。
- [ ] 固定疫苗、变异、外部输入及医疗容量是否启用；未启用的机制也写明，不把库具备的功能自动变成新增动作。

**2．观测白名单：LLM、RL 和阈值都能知道什么**

以下是新协议需要落实的字段范围，尚不是现有代码已经完成的接口。

| 类别 | 共同可用的信息 | 要确认的细节 |
|---|---|---|
| 日期与任务 | 当前决策日、总人口、已公布的评价时域、公开场景类型与聚合结构 | 是否提供剩余天数；人口类别/目标群体总量如何编码 |
| 诊断 | 截至前一日实际已交付的新增/累计诊断、周汇总与趋势 | 采样日与报告日区分、延迟、重复诊断、缺失记录 |
| 检测 | 已实施检测次数，按概率检测与周期筛查分项，及诊断/检测代理比 | 按检测人次或独立人数；是否共享资源；重复检测 |
| 处置与运营 | 已知隔离/检疫人数、公开负担和已交付追踪通知；可记录的资源使用 | 日终统计、隔离与检疫分项及并集；通知人次与人数区分 |
| 动作与资源 | 当前执行组合、各维持续时间、当前公开容量、合法动作集合 | 使用请求或执行动作；单位与生效时点；资源变化公告时点 |
| 共同历史 | 最近 4 周公共观察和已执行动作 | 时间排列、有效长度、空历史、末尾不足周、填充值 |
| 额外经验 | 完整 LLM 使用合规的短期组织和源域案例检索 | 这是被消融的算法模块，不能额外暴露真实疫情状态 |

按现有 plan，以下 **不得进入观察、提示、检索键、案例反馈或控制器可读 info**：

- 真实新增/累计感染、真实暴露/感染/康复状态、真实患病率及感染增长率。
- 诊断数/真实感染数、真实 `R_e`、真实传播层贡献、`infection_log` 中传播源。
- 本回合隐藏的 `beta`、传播系数、外部输入实现、个体感染时间/恢复时间/易感性。
- 尚未交付的阳性结果、未来诊断日期、未来资源事件日期或轨迹。
- 从上述真值算出的奖励/总回报、反馈摘要、风险标签和提前终止信号。
- 通过 world seed、low/medium/high 隐藏参数标签、内部 run ID 或文件名绕过白名单的信息。

需要逐项冻结：

- [ ] 只提供聚合公共记录还是也提供登记在册的公开分组统计；分组/年龄/角色信息的粒度、分母和可获得性。
- [ ] 将公共观察、源域训练奖励和私有分析日志分开；训练器可以读取奖励，冻结测试控制器不能把真值奖励作为下一步输入。
- [ ] 允许执行器内部使用个体索引和模拟状态以执行检测/追踪，但不给中央控制器反馈目标人群的真实阳性构成。
- [ ] 固定所有基础特征公式、单位、舍入与顺序；LLM 文本和 RL 编码不得因遗漏字段形成额外信息差。
- [ ] 固定周增长率在“前周为 0、本周大于 0”时的处理；缺失、空历史和真实零分开。当前 `_growth_ratio()` 此情形返回 1，需重新明确。
- [ ] 固定诊断/检测比的分母、报告错位和零检测日规则；称为代理指标，不称准确阳性率。
- [ ] 固定趋势的容差、窗口长度、极小计数处理；是否提供原始量、每千人量或两者。
- [ ] 固定历史填充、有效天数/周数、是否允许不完整首周、首次无历史的表示。
- [ ] 固定数值归一化范围、裁剪规则与异常值；若源域拟合归一化，只使用源域训练资料，验证/测试不 refit。
- [ ] 固定已知隔离/检疫等运营记录的交付时点，不读取隐藏的未来解除日期作为观察。
- [ ] 已定首版不新增 R_e 估计器或传播层归因估计器；症状、住院和死亡等也不因模拟器存在对应真值就自动进入观察，若另有已商定的公共记录，需要明确报告来源与延迟。
- [ ] 将公开先验、专家知识注入和当前观察分开定义；无记忆 LLM 保留相同专家知识与基础 4 周历史。

**已发现的关键问题：** [people.py](../covasim/people.py) 的 `check_diagnosed()` 按采样日计数未来阳性结果，返回 `test_pos_inds`；实际交付日由 `date_diagnosed=t+test_delay` 控制。因此现有 `results["new_diagnoses"]` 在延迟大于 0 时不等于已交付诊断。只将 `new_infections` 替换成 `new_diagnoses` 不能完成信息隔离，应新增实际交付公共事件记录。追踪 `known_contact=True` 也可能在未来通知尚未到达时提前设置，不能直接据此判断已通知。
