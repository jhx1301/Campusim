**全局记忆来源扩展建议：基础对照、强化学习与 LLM 的混合经验库**

本文件回答“是否需要加入 LLM 生成的轨迹”。属于研究建议，尚未修改当前协议、采集器、案例库或实验结果，也未启动模型调用、训练或采集。

**建议结论**

建议把关闭全局检索的 LLM 作为新增经验来源，同时保留现有四类来源，并在 PPO、Double DQN 正式训练和选模完成后加入其执行轨迹。是否最终保留全部来源，应由覆盖情况和独立开发模拟上的闭环效果决定，不能根据最终测试赢家选库。

不建议把“LLM 生成”当成优质标签，也不建议把所有非 LLM 轨迹替换为 LLM 轨迹。目前没有正式建库和对照结果证明四类来源无效，或证明 LLM 来源一定优于其他来源。

**目前记忆实际保存什么**

当前 [PublicCase](../cemas/control/memory_types.py:223) 保存决策前公共观察、实际执行的一周记录、至多随后一周的记录、持续时间及不确定性标记。案例描述由[固定模板](../cemas/control/memory.py:219)生成，不保存源控制器的推理文字，也不向模型提供私有感染真值或奖励。

因此，加入 LLM 执行轨迹，首先改变的是能够检索到的状态、措施与后续观察分布，不会自动向模型提供之前 LLM 的推理过程。这里利用的是上下文中的经验，不是直接更新模型参数。即使轨迹来自简单控制器，也可能提供有用观察，例如诊断下降同时检测量也下降时，不能据此认定疫情改善。

当前案例只有本周和接续一周的主要后效，不等于完整的长期决策经验。添加更复杂的生成者不能自动解决观察时间过短、后续动作改变或因果解释不足的问题。第一轮建议保持案例表示和检索方法不变，仅研究数据来源；若未来研究多周决策片段或有依据的简短决策说明，应单独设置对照，不同时归因于 LLM 轨迹。

**为何需要多种来源**

| 来源 | 主要用途 | 局限 |
|---|---|---|
| 最低和当前资源允许的最强干预 | 提供干预边界及负担参照 | 缺少复杂调整过程 |
| 随机可执行动作 | 补充动作组合与转移的覆盖 | 可能产生不连贯的策略，不能当作推荐答案 |
| 调优阈值 | 提供可解释的响应和持续控制轨迹 | 仍受预设阈值结构限制 |
| 已训练、选定参数的 PPO 与 Double DQN | 补充非 LLM 的自适应策略 | 不应假设已充分训练或始终优于阈值；必须有正式选模证据 |
| LLM，允许本回合短期摘要但关闭全局检索 | 补充更接近 LLM 实际决策的状态和动作，以及它自身常见的失误 | 可能重复同一种保守策略，或使同类错误在经验中重复出现 |

来源复杂不等于案例有用。入库重点应是公开记录完整、实际动作清楚、资源条件可比、重复受控、覆盖充分，以及保留不同观察结果。不能按隐藏感染收益将案例包装成“正确干预”，也不只保留 LLM 的低感染回合而删除反例。生成者身份和私有评估仍放在独立来源记录中，不以“这是 LLM/RL 的建议”作为模型采纳案例的理由。

**推荐的候选规模**

一个可执行的候选方案是在原有27个建库初始条件上生成七类轨迹：

- 现有四类：27×4=108条；
- PPO和Double DQN：27×2=54条；
- 关闭全局检索的LLM：27条；
- 合计189条，而不是189个独立疫情。它们仍只有27组初始条件，同组不同策略的轨迹相互关联。

189只是候选配置，不是已证明最优的规模或比例。正式训练得到的每种RL算法有三个模型时，可将三个模型均衡分配到各传播/容量组合的三个重复初始条件，不按建库或测试收益挑选最好模型。源轨迹由训练结束的控制器在专门建库条件中重新运行，不能直接把训练回放、选参模拟或最终测试轨迹混入案例库。

为控制成本，先在每个传播/容量组合选一条建库条件，试采9条LLM轨迹，检查它们是否补充了不同状态、动作转移和维持时长，以及能否在开发查询中被检索到。若只是重复已有的最强干预，不能因其来自LLM就认为有必要采满。若最终生成设置不变，9条可计入27条；若设置改变，旧数据应另存版本并如实登记。

H=112天时，27条LLM轨迹需要27×16=432次按周决策，9条试采为144次，均未计重试。另有54条RL执行轨迹，但不额外增加算法类型。实际token、延迟、费用和训练成本需分别实测；这些数量不是已经发生的调用或运行授权。

**LLM 建库流程**

1. 在生成最终建库轨迹前确定模型、提示词、知识和公共信息规则。
2. 建库LLM可使用本回合的短期摘要，但关闭全局检索；避免用尚在变化的案例库生成新案例，又把结果当作固定经验来源。
3. 保留当时可观测状态、实际执行动作、持续时间、资源消耗和随后已经交付的反馈。模型请求被调整或回退时，记录真实执行结果，不能把原提议当作已经发生的措施。
4. 保留有效的高负担、低负担和不利观察结果。对后续措施改变、检测量改变、反馈截短等情况继续明确标注；后续诊断变化不自动证明某一动作的因果效果。
5. 新增来源通过同一套公共字段检查和来源核验后，生成固定版本；目标测试期间只读，不追加测试经验。

LLM 建库与评价可以包含相同传播、容量设置，但必须使用不同初始疫情记录，并与调参、最终测试数据分开。这检验已知设置下的新疫情，不自动等于分布外泛化。用于模拟城市迁移的目标轨迹也不能预先加回校园源库后再声称零适配迁移。

若未来希望保存源 LLM 的解释，优先考虑与当时公共证据相连的简短说明；模型自述的“成功”“因果解释”不能直接当作真值。不要把新增解释字段、反思模块、检索算法修改与来源扩展同时进行后，只将收益归因于“加入LLM轨迹”。

**最小的来源对照实验**

先收集候选源数据，再构建以下三类可比较的库：

| 条件 | 经验来源 | 回答什么 |
|---|---|---|
| A | 当前四类非LLM来源 | 原始来源方案是否足够 |
| B | 四类来源加PPO/DDQN | 自适应的非LLM经验是否已能补齐主要缺口 |
| C | 四类来源加PPO/DDQN，再加入LLM | LLM经验是否提供超出非LLM经验的额外价值 |

为研究来源而非单纯数据量，各条件抽取相同数量的有效案例，传播/容量组合及时间阶段的比例一致。固定抽样规则或重复几次预先确定的抽样以报告样本选择波动；不要挑一次有利抽样。动作分布不必被强行做成相同，因为补充动作覆盖正是要检验的机制，但须报告其差别。全量候选库的可部署效果可另报，不能与等量来源对照混为一项结论。

所有条件使用同一评估LLM、基础四周历史、专家知识、短期摘要设置、检索方法、每次案例上限和输入预算。固定案例条数并不保证实际输入token相同；各条件实际检索条数、token与费用照常报告，不填入无关案例凑长度。

第一轮保持现有检索器不变，检查新增LLM案例是否进入合格候选、实际被发送、与其他案例是否重复或冲突，以及控制器是否改变了决策。引用率只是使用诊断，不能代替控制收益。开发世界的留出必须整组排除同一初始条件下的所有控制器轨迹，不能留下同一疫情的其他策略版本。

在不参与建库与调参的模拟中比较感染、各类负担和不确定性，再确定库组成，最后固定方案开展独立测试。若用独立测试进行论文对照，所有库版本及比较方式须事先确定，不根据测试结果再次选库。

如果C在同等案例量下不能优于B，就没有证据把LLM来源作为必要组件；若仅全量C有效而等量C没有优势，可能是数量或覆盖增加的作用。若C能以更低感染且不增加主要负担取得改善，才更有依据保留LLM来源。多个负担方向冲突时报告权衡，不重建CPBU总体排名。

**公平性与成本解释**

PPO/DDQN轨迹来自训练好的控制器，因此LLM系统利用了这些控制器产生的外部经验。论文不能将结果概括为“不借助任何训练经验的LLM击败RL”。应披露这些经验的生成成本，包括训练好的控制器、额外模拟和LLM采集调用；共同使用的产物注明成本共享方式，不能将采集成本隐去。

**现有实现的边界**

当前 [SOURCE_POLICIES](../cemas/control/memory_store.py:21)、[采集器](../tools/collect_observable_memory.py:33)、[协议](control_protocol_v1.json:782)及[发布检查](../cemas/control/artifacts.py:497)仍围绕四类来源和108条正式轨迹。LLM/RL新增来源不是当前已经验收的采集能力；采纳本方案需明确修改来源登记、控制器接入、模型身份记录、覆盖报告及发布数量检查，保留旧版本。本轮不修改这些代码或现行协议。

**相关研究的适用程度**

[DiLu](https://proceedings.iclr.cc/paper_files/paper/2024/hash/93c936b9e492def9c00782cab79dbc6d-Abstract-Conference.html)使用包含记忆与反馈的LLM决策框架；[Reflexion](https://arxiv.org/abs/2303.11366)研究用任务反馈及语言反思辅助后续决策，而不更新模型权重。它们说明利用交互经验是值得检验的方向，不构成本任务中“LLM来源必然更好”或“必须增加反思模块”的证据。上述混合库及对照方案是针对本项目的研究建议，效果尚待验证。
