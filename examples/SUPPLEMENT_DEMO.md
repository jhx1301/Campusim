# CEMAS supplementary-video demo

> Historical demo for the previous P0–P4 policy and embedding memory stack.
> Its population, observation and policy format are separate from current V1;
> it also requires the external local database and model cache described below.
> Current V1 commands and calibration prerequisites are in the
> [project README](../README.md) and [UW integration contract](../docs/uw_control_integration.md).

`t22_supplement_system_demo.py` is a short, deterministic demonstration of the
complete CEMAS decision loop. It is designed for recording a paper supplement
and does not require an API key or network access.

## Run

From the repository root:

```bash
E:/pytroch/anaconda3/envs/simulation/python.exe \
  examples/t22_supplement_system_demo.py --pace 1.2
```

The default run uses 1,200 people, a 21-day horizon, and policy decisions every
7 days. It requires the frozen historical-memory database at
`E:\tempt\data\memory_build.db` and a locally cached
`paraphrase-multilingual-MiniLM-L12-v2` SentenceTransformer model. The database
is opened through SQLite's true read-only mode. If the database, complete
cases, vector dimensions, or cached model are unavailable, the demo stops with
an English error instead of falling back to one memory branch.

`--pace 1.2` leaves 1.2 seconds between narrated decision stages for screen
recording; omit it for an immediate run. After the simulation and exports
complete, one looping animated dashboard opens automatically. It shows:

1. the epidemic curve growing day by day;
2. the executed policy trajectory;
3. daily transmission contributions from all six contact layers;
4. the observation, side-by-side short-term and long-term memory cards, policy
   selection, and executed intervention at each decision day.

At each decision day, the animation highlights Observation, Short-term Memory,
Long-term Memory, and Policy and Intervention in sequence. Both memory cards
remain visible throughout the sequence. After the fourth stage at Days 7, 14,
and 21, playback stops and cannot advance until you click inside the animation
window. Press `Space` to pause or resume on ordinary days, `R` to replay from
Day 0, and `Esc` to close it. The decision gates still require a mouse click;
the Space key does not bypass them.
The three static publication-quality figures are still saved in the output
directory.

For a headless check that only saves files:

```bash
E:/pytroch/anaconda3/envs/simulation/python.exe \
  examples/t22_supplement_system_demo.py --no-show
```

Outputs are written to `results/supplement_demo/`:

- `02_demo_dashboard.png`
- `03_decision_storyboard.png`
- `decision_audit.jsonl`
- `decision_story.json`

- `policy_trace.csv`
- `key_metrics.json`

## What is deterministic

The demo uses the production CEMAS campus population, contact network,
simulation, state extraction, dual-branch memory, policy response validation,
and intervention execution. Short-term memory is produced from the current
1,200-person run. Long-term memory retrieves real normalized comparisons from
the frozen 40,000-person historical corpus; the display intentionally omits
non-comparable absolute historical counts. For reliable recording, the
external LLM request alone is replaced by a deterministic response replay. The
demo disables the optional single-level policy-transition constraint, so the
final decision can move directly from `P3_strong` to `P1_guarded`. This
configuration is explicitly identified in the output metadata.

Use this script to demonstrate the system workflow, not to claim that the
displayed decisions were generated by a live LLM call.
